1. What is the Design Language?

The Design Language project was built to provide design styleguides and a component library to be used across ALL applications within Marketing IM.

2. Who should use this resource?

Anyone interested in our design standards, but it's mainly intended for developers. If there's something you cannot find or you need assistance, please check the Stack Overflow page or post a question in the Slack 'core-ui' channel

3. Where do I begin?

After you've set up Design Language, you'll be able to use the components listed below. If you need sample markup, please visit the Page layout examples. Do not use Bootstrap

Bootstrap

If you see bootstrap in your package.json, please uninstall it as it breaks our css. We use 'Flex' for layout and mobile adaption.

instead we use Flex which is a far cleaner approach, easy to use and very effective for responsive layouts

4. How do I use a component in my project?

When you've found the component you want to use, either by browsing the full list below, using the left navigation or Search facility, click on the View gist button to access the markup. You'll also find an Attributes table on all the component pages

Configure your app files

Add the Design Language Styles

In your project angular.json call the styles file from the node package.
Ensure the Anglo one is last.

  1. "styles": [
  2.     "path/to/all/other/scss/files.scss",
  3.     "node_modules/@angloamerican/styles/src/scss/styles.scss"
  4.  ],

Add the Design Language Components

In your project app.module.ts or shared.module.ts import the modules

  1.  import {
  2.     AnimationsModule,
  3.     ElementsModule,
  4.     LayoutModule,
  5.     NavigationModule,
  6.     PatternsModule,
  7.     WidgetsModule
  8.  } from '@angloamerican/components';

and declare them under @NgModule > imports

  1.  imports: [
  2.     AnimationsModule,
  3.     ElementsModule,
  4.     LayoutModule,
  5.     NavigationModule,
  6.     PatternsModule,
  7.     WidgetsModule
  8.  ],

In your project tsconfig.json declare the Components paths.

  1.  "paths": {
  2.     "@angloamerican/components": [ "node_modules/@angloamerican/components" ],
  3.     "@angloamerican/components/*": [ "node_modules/@angloamerican/components/*" ]
  4.  }

Setup

Create a basic html page with your preferred HTML editor. Set your default font family, weight, line-height and size on the body element:

<body style="font-family: Roboto; font-size: 12px; color: #323232; margin:0; padding:20px; line-height: 17px"></body>

For the construction of the template, use a table inside the body and set the cellpadding to at value of at least 10, as this will help with section spacing.

<table align="center" border="0" cellpadding="10" cellspacing="0" width="600">

You can’t use stylesheets in the conventional manner, instead you have to go back to basics and use inline css on the actual element itself. If you were thinking of using the block at the top of you’re page, don’t, as that won’t work either.

Try and use conventional html tags for aesthetics and layout. For example, use the strong tag for bold text rather than setting a style with font-weight: bold to the element. Likewise, utilise the heading tags h3, h2, h1 etc for small, medium and large headings. For spacing sections in your template, try and use new table rows, that's where the cellpadding you set earlier with come into play, It’s more effective that using margins and padding as these are also ignored by most email clients. For large areas of text, use the paragraph tag as you would normally.

Using images

If you want to use images in your template, you will need to either host them where your recipients have access or embed them in the html template itself. If you choose to embed them (and this is the easiest option) the source image must be a bitmap file such as a PNG, GIF or JPEG you cannot embed vector-based images such as SVG. When your bitmap image is ready, use this tool to generate a data url.

When you’ve generated the data url, copy and paste it to the source of your image tag like so…

<img src=”the dataurl you copied earlier” alt=”your image name” />

Creating grids and charts

Use nested tables for grid layouts. If you want unified columns with spacing, you’ll need to set the width of the first cell.

<table>
   <tbody>
    <tr>
      <td width="150"><strong style="color:#0075b0">Name</strong></td>
      <td>Paul Smith</td>
    </tr>
    <tr>
      <td width="150"><strong style="color:#0075b0">Job Title</strong></td>
      <td>Project Manager</td>
    </tr>
    <tr>
      <td width="150"><strong style="color:#0075b0">Country</strong></td>
     <td>United Kingdom</td>
    </tr>
  </tbody>
</table>

Sending your email template via Outlook 365

Step 1 - Click the small quick access cheron in the header

Step 2 - Click 'More Commands'

Step 3 - Find 'Attach File' option and click 'Add'

Step 4 - Click 'OK'

Step 5 - Click the small paperclip icon that's now added

Step 6 - Browse for your HTML file and then select 'Insert as Text'

Step 7 - You now have your template displayed (May need tweeking)

Tidy things up in Outlook or other client

When you have the template open in Outlook, it will most likely look a bit different than your browser version. For example, your images might not appear at the correct size, the font you chose will default to Outlooks default font etc. I would suggest at this point, tidy things up as best you can. Select all and reset your font family, drag images to scale to the correct size and modify font sizes until you’re happy, you can also set the email background to a chosen color if required.

Why should you use them?

In Anglo American, we design applications that users use extensively. They can forgive less-than-perfect functionality as they are expert users and know their tasks. Nevertheless, our designs should offer an experience that is confidence-building and optimal.

These design principles offer fundamental advice for making easy-to-use and pleasing designs. They outline ways to improve usability, influence user perception of systems, increase the appeal and help you make effective design decisions in your projects.

"Design used to be the seasoning you'd sprinkle on for taste; now it's the flour you need at the start of the recipe."

Complimentary resources

These design principles support the Design Language project, which provides style guides and a component library used across ALL applications within Marketing IM.

It is important to prioritise a design approach that minimises users' cognitive load and decision-making time and optimises data usage. Also, we can achieve consistency across the Anglo digital landscape if we follow these principles.

"Accessibility means that all people can perceive, understand, navigate, and interact with digital information"

  1. Use plain language and avoid confusing content
  2. Ensure there is visible focus style for interactive elements that are navigated to via keyboard input
  3. Make sure all 'img' elements have an 'alt' attribute
  4. Ensure the viewport zoom is not disabled
  5. Provide a text alternative for complex images such as charts, graphs, and maps
  6. Use heading elements to introduce content and use one H1 element per page/view
  7. Ensure that links are recognisable as links and if they open in a new tab or window, inform the user
  8. Maintain good proximity between content, but enough space to not be visually overpowering
  9. Maintain good colour contrast

"True interactivity is not about clicking on icons or downloading files, it's about encouraging communication"

  1. Understand the purpose of your design and stick to it. If you deviate, it will cause confusion
  2. Use simple language - jargon requires prior knowledge, this might not be the case
  3. Keep users informed with constant feedback (includes errors, page load and system status)
  4. Make sure that error, warning, and success states are not visually communicated by just colour
  5. If errors are possible, ensure users are informed prior to error, through validation and error handling
  6. Do not expect users to remember information, keep options and instructions always visible
  7. Choose the correct component. If the user needs to provide a simple binary response, make sure your design only asks them that
  8. Stick to the Design Language style guidelines as it offers familiarity and consistency

"Learnability is the ease and speed with which users learn to interact with a system, application or service"

  1. Do not fear simplicity. Even expert users will appreciate being able to do their complex tasks easily, and novice users will learn quickly
  2. Make items easy to find
  3. Keep users informed with constant feedback (includes errors, page load and system status)Remove mundane, repetitive tasks (like copy and paste) and have the system support these processes
  4. Use the power of defaults. If we know how the user will answer, then have that selected first. It shows that we understand the user and reduces the time taken to complete their task
  5. Explain to a user exactly where they are and what is going on, and where to go next
  6. Repeat the same interaction with the same outcome: this will reinforce how it works and provide consistency
  7. Remove distractions. Let the user know their route by performing tasks consecutively, not simultaneously

"Good navigation seamlessly takes users where they want to go"

  1. Page hierarchy - ensure a user knows where they are in the application and that they can get back to where they came from (and forward if available)
  2. Ensure that navigation elements have correct weight in the design. Do not let them get lost in the page
  3. Set information in a natural, logical order
  4. Choose the correct type of navigation - menu items, tab menus, hyperlinks. And ensure your user knows what to do to progress with their task
  5. Put navigation items in familiar locations, place them where a user expects them to be
  6. Make labels easy to scan and understand, clearly describe what the navigation does
  7. Make menu links look interactive if they are. Don't make content look like a link if it isn't

"It doesn’t matter how many times I have to click, as long as each click is an unambiguous choice. Don’t make me think"

  1. Never assume that the user will know what to do, make sure your design is aligned directly to their goal
  2. Maintain consistent interactions - so users know what to do next
  3. Make every design element have a purpose
  4. Allow users to easily undo/redo actions
  5. Concentrate on achieving clarity by bringing only useful features to the user's attention
  6. Aim for efficiency. Don't make a user to repeat a task (no double keying of data) Let the system do the heavy lifting
  7. Test your design with your users and be happy to change it based on their feedback
